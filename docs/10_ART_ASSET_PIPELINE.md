# 10 — ART ASSET PIPELINE

> **Status:** Specification. Nothing in this document is implemented yet.
> **Purpose:** Make the project *ready* for beautiful assets rather than making mediocre assets increasingly complicated.
> **Authority:** `design/references/` is the visual direction. This document does not change the world, the layout, the camera, or any approved decision.
> **Supersedes:** `10_ART_ASSET_PLAN.md` (folded in and removed).
> **Last updated:** 2026-08-29

---

## 0. The blocking constraint, stated once

**There is no 3D authoring or 3D generation tool in this environment.** Verified, not assumed:

| Tool | 3D authoring? |
|---|---|
| Artlist MCP | **No** — images, video, music, voice-over only |
| Context7 | Documentation only |
| Playwright / Chrome DevTools | Validation only |
| Caveman plugin | Prose style + three *code* subagents. No world-design critic exists. |
| Figma MCP | 2D design |

M4B's procedural authoring was therefore not a stylistic choice. The world reads as procedurally generated because it *is* — generated by an engineer, with no artist and no modelling tool.

This document specifies the machinery that turns "we have beautiful assets" into a one-line change per asset, and specifies precisely what those assets must be so they can be commissioned, bought, or authored in Blender.

**What I can build without any asset existing:** everything in §3–§9, §15–§19.
**What remains blocked:** the assets themselves (§10, §11) and the reference sheets that specify them (§14).

## 1. Art pipeline overview

```
  Gemini reference sheet          ← art direction, per asset (§13, §14)
            ↓
  DCC authoring (Blender / commissioned / licensed pack)
            ↓
  Optimise: decimate, weld, flat-shade, atlas UVs
            ↓
  Export GLB  +  KTX2 texture atlas
            ↓
  public/assets/environment/…
            ↓
  Asset registry entry flips  procedural → glb        ← the only code change
            ↓
  Loader → cache → shared material → instanced / LOD
            ↓
  World
```

Two halves, deliberately separated:

- **Engineering (mine):** registry, loading, caching, disposal, instancing, LOD, materials, budgets, validation.
- **Art (not mine):** silhouettes, textures, the reference sheets that define them.

The pipeline's entire job is to make the seam between them a data edit.

## 2. Asset lifecycle

```
DECLARE      logical id + spec added to the registry, source = procedural
   ↓
PLACEHOLDER  existing procedural builder serves it; world is playable
   ↓
SPECIFY      reference sheet authored (§14)
   ↓
AUTHOR       GLB + atlas produced externally
   ↓
INGEST       dropped into public/assets/…, registry entry flipped to glb
   ↓
VALIDATE     §18 checklist — scale, pivot, orientation, budget, silhouette
   ↓
TUNE         placement, LOD distance, instance counts
   ↓
LIVE
   ↓
DISPOSE      geometry/material/texture released on unmount
```

At no point does gameplay code change. `PlayerController`, `FollowCamera`, the interaction system and the content system only ever see a transform and a `contentKey`.

## 3. Asset registry design

One module is the single source of truth for what an asset *is*.

```ts
export type AssetId =
  | 'tree.oak.broad' | 'tree.oak.tall' | 'tree.birch' | 'tree.conifer'
  | 'dest.experience.cabin' | 'dest.projects.desk' | 'dest.education.desk'
  | 'dest.achievements.shrine' | 'dest.experience.props'
  | 'prop.bridge' | 'prop.rock.a' | 'prop.rock.b' | 'prop.rock.c'
  | 'veg.grass' | 'veg.lupine' | 'veg.daisy' | 'veg.clover'
  | 'veg.shrub' | 'veg.reed'

type Source =
  | { kind: 'procedural'; build: () => BufferGeometry; material: MaterialKey }
  | { kind: 'glb'; url: string; lods?: { url: string; distance: number }[] }

export interface AssetSpec {
  id: AssetId
  category: 'tree' | 'destination' | 'prop' | 'vegetation'
  importance: 'P0' | 'P1' | 'P2'
  source: Source
  /** instancing hint — how many of these exist in the world */
  expectedInstances: number
  castShadow: boolean
  /** mobile: multiplier applied to instance count, 1 = unchanged */
  mobileDensity: number
}

export const ASSET_REGISTRY: Record<AssetId, AssetSpec>
```

**The swap:** change `source` from `{ kind: 'procedural', build: buildHeroOakBroad }` to `{ kind: 'glb', url: '/assets/environment/trees/hero-oak-broad.glb' }`. Nothing else moves.

### Resolution hook

```ts
useWorldAsset(id): { geometry: BufferGeometry; material: Material }
```

Suspends on GLB load, returns immediately for procedural. Callers cannot distinguish the two.

## 4. GLB loading architecture

**Verified: every loader and decoder needed already ships with `three`. No dependency is required.**

| Need | Module | Decoder binary |
|---|---|---|
| GLB | `three/examples/jsm/loaders/GLTFLoader.js` | — |
| Draco | `three/examples/jsm/loaders/DRACOLoader.js` | `three/examples/jsm/libs/draco/` → copy to `public/decoders/draco/` |
| KTX2 | `three/examples/jsm/loaders/KTX2Loader.js` | `three/examples/jsm/libs/basis/` → copy to `public/decoders/basis/` |
| Meshopt | `three/examples/jsm/libs/meshopt_decoder.module.js` | bundled, no copy needed |

A `postinstall` script copies the decoder binaries into `public/decoders/`, so they are served rather than bundled.

### Loader singleton

One `GLTFLoader`, configured once with all three decoders, shared across every load. KTX2Loader requires `detectSupport(renderer)` — so it is initialised inside the canvas, after the renderer exists.

### Caching and disposal

- `Map<AssetId, Promise<LoadedAsset>>` — a given GLB is fetched once per session
- Loaded geometry and materials are **shared**, never cloned per placement
- Disposal releases geometry, material and texture on world unmount; the cache is cleared with it
- The world is never unloaded during normal play, so disposal exists for correctness, not for churn

### Loading groups

Per `docs/09` §18, unchanged:

| Group | Contents | Gate |
|---|---|---|
| **Critical** | player, terrain params, 2 hero trees, 4 destination structures, shared atlases | blocks entry; drives the progress bar |
| **Secondary** | secondary trees, rocks, props, bridge | loads after entry, world already playable |
| **Deferred** | backdrop, night-only assets | idle |

Progress is real. A failed secondary asset must not block entry or crash the world.

## 5. Texture architecture

Five shared atlases. Not per-asset maps.

| Atlas | Size | Consumers |
|---|---|---|
| `bark-foliage` | 1024 | hero oak ×2, birch, conifer |
| `timber` | 1024 | cabin, all desks, bridge, shrine posts, crates |
| `stone` | 1024 | rocks, chimney, dais, shrine base |
| `vegetation` | 512 | grass, lupine, daisy, clover, reed, shrub |
| `props` | 512 | blueprints, books, metal, cloth |

- **KTX2 / Basis** compressed, mipmapped, `SRGBColorSpace` on colour maps only
- **No normal maps** unless a specific asset proves it needs one — the style is painted, not lit-by-texture
- **No metalness/roughness maps.** Lambert-class materials; the look comes from painted value, not PBR response
- Anisotropy conservative (≤4)
- Target **≤ 24 MB** texture memory total

**Shipped practice (DD-34, recorded 2026-09-18).** The nine approved GLBs each carry **one 256 × 256 base-colour palette PNG** (8 × 8 cells, per-face UV cells, ~1.3–1.7 KB), **no normal / AO / metallic-roughness texture**, `metallicFactor = 0` and a **scalar** roughness (0.92 matte; 0.82 / 0.22 / 0.40 on the Explorer's palette, visor and emissive; 0.60 on the desk screen). Total texture cost is negligible against the 24 MB target. Two divergences from the table above are recorded, not resolved: assets carry **their own** palette rather than the five shared atlas files, and KTX2 compression is not in use (the palettes are small enough that it has not mattered). Consolidation remains an optimisation, and the shared 8 × 8 cell layout makes it mechanical.

### The style rule that matters

Painted stylization, never photographic. Wood = subtle grain + dark joints + edge highlights + warm variation. Stone = designed facets + painted value + moss accents. Leaves = grouped masses with hue variation, never individual leaves. **Texture detail must not become noise.**

**How that is achieved here (DD-35).** Through **palette cells and geometry**, not texel detail: a dark joint is a cell, a birch's lens mark is a cell, a moss accent is a cell on an upward-facing plane. "Painterly" is the value language to reproduce — base → highlight → shadow — not an instruction to paint surface detail into a map.

## 6. Material strategy

One material per atlas, shared by every consumer of that atlas.

```
bark-foliage → 1 material   (alpha-tested where foliage cards need it)
timber       → 1 material
stone        → 1 material
vegetation   → 1 material   (alpha-tested, double-sided)
props        → 1 material
terrain      → 1 vertex-coloured material   (procedural, no texture)
water        → 1 transparent material
sky          → 1 unlit
distant      → 1 unlit vertex-coloured
emissive     → 1 (the amber accent — screens, lamps, lantern)
```

**Ceiling: 12 materials for the entire world.** Every unique material is a state change.

GLB-authored materials are **replaced at ingest** with the shared atlas material — an imported asset never brings its own material into the scene. This is what keeps the count fixed regardless of how many assets arrive.

Alpha-**tested** only. Never alpha-blended: blending costs sorting and overdraw, and transparency budget is reserved for water alone.

**Shipped practice (DD-34/DD-35, recorded 2026-09-18).** Authored assets name their material for its atlas family — `bark-foliage`, `timber`, `stone` — and add a second only for a genuinely different surface (the desk `screen`, the Explorer's `visor` and emissive). **Replacement at ingest is not implemented**: assets currently keep their own material, which the measured 52–71 draw calls have not made a problem. Every approved asset is `OPAQUE`; both hero trees ship as **faceted foliage masses with no alpha cards**, so the alpha rule above is currently unexercised (C-7).

## 7. Instancing strategy

| Asset class | Technique | Why |
|---|---|---|
| Vegetation (grass, flowers, reeds, shrub) | `InstancedMesh` | thousands of identical geometries |
| Rocks | `InstancedMesh` per variant | 40–60 placements, 3 variants |
| Trees | `InstancedMesh` per type | 6–30 placements each |
| Backdrop ring | `InstancedMesh` | 220 placements, unlit |
| Destination sets | merged static geometry | different geometries, shared material → one draw call each |
| Bridge, player | merged static geometry | currently un-merged; the remaining draw-call offenders |

**GLB → InstancedMesh adapter:** on load, traverse the GLTF scene, extract the first mesh's geometry, discard its material, bake any node transform into the geometry, and hand back a single geometry ready for instancing. Authored and procedural assets then instance through identical code.

**Spatial partitioning:** instances are grouped into spatial buckets so frustum culling still works. One world-spanning `InstancedMesh` defeats culling entirely — this is a known trap and is called out in `docs/09` §15.

Variation comes from transform only: scale, rotation, position, mirroring. Never from new geometry.

## 8. LOD strategy

LOD is applied **only where measurement justifies it**, not by default.

| Asset | LOD0 | LOD1 | Switch |
|---|---|---|---|
| Hero oak broad | 2,500–4,000 | ~800 | ~45 u |
| Hero oak tall | 2,000–3,500 | ~600 | ~45 u |
| Experience cabin | 3,000–5,000 | ~1,200 | ~55 u |
| Achievements shrine | 2,500–4,000 | ~1,000 | ~45 u |
| Birch | 600–1,000 | ~250 | ~40 u |
| Conifer | 400–800 | ~200 | ~40 u |
| Workshop props | 1,500–2,500 | culled | ~30 u |

Everything else has a single level. Vegetation uses **density reduction with distance**, not geometric LOD — cheaper and visually better.

LOD meshes are authored as separate GLBs (`…-lod1.glb`) and declared in the registry's `lods` array. `THREE.LOD` handles switching.

## 9. Mobile strategy

Same world, same art direction, lower density. Never a separate asset set.

| Knob | High | Low |
|---|---|---|
| `dpr` cap | `[1, 2]` | `[1, 1.5]` |
| Vegetation instances | ×1.0 | ×0.25–0.33 (`mobileDensity`) |
| Shadow map | 2048 | 1024 or 512 |
| LOD switch distance | as §8 | ×0.6 (switch earlier) |
| Workshop props | on | culled |
| Texture sampling | full | mip bias, no separate texture set |
| Backdrop ring | 220 | ~90 |
| Water | scrolling normal | static surface |

Tier chosen by **measured frame time**, not user-agent. A low tier looks simpler; it never looks differently art-directed.

The eight assets that most determine whether the world reads premium or procedural. Fields follow the Phase C schema.

### 10.1 `tree.oak.broad` — Hero Tree A

| Field | Value |
|---|---|
| Category | tree |
| Importance | **P0** |
| Visual role | Shelters the Projects and Education desks. The most-seen silhouette in the world. |
| Silhouette | Asymmetric, wider than tall, **deliberate negative space between foliage masses**. Must read as an authored tree when rendered as a flat black shape at 40 units. No spherical canopy. |
| Material | bark-foliage atlas. Painted bark with vertical grooves; foliage with 3–4 hues, warm sunlit top, cool dark underside. |
| Texture | shares 1024 atlas |
| Triangles | 2,500–4,000 (LOD1 ~800) |
| Materials | 1 |
| LOD | 2 levels, switch ~45 u |
| Reuse | 6 placements, instanced, varied by rotation/scale/mirror |
| Mobile | LOD1 earlier; no count reduction (hand-placed) |

**Construction notes:** root flare meeting the ground, 3-segment leaning trunk, 5 branches at genuinely varied angles and lengths, foliage as 3–4 *grouped* masses rather than 8 blobs. Canopy underside must clear 5.0 units (the desktop camera sits at 4.2; see `docs/09` F3/F6).

### 10.2 `tree.oak.tall` — Hero Tree B

As above, but **taller and narrower**, canopy gathered rather than spread. Must not read as A rescaled — different branch rhythm, different crown shape. Backs the cabin and shrine without competing with their rooflines. 2,000–3,500 tris, LOD1 ~600, 4 placements.

### 10.3 `dest.experience.cabin` — Experience Cabin

| Field | Value |
|---|---|
| Visual role | **The only roofline in the world.** Strongest landmark; visible from spawn at 58 units. |
| Silhouette | A-frame gable with a stone chimney breaking the ridge. Must read as architecture at 58 units through fog. |
| Material | timber + stone atlas |
| Texture | 1024–2048 |
| Triangles | 3,000–5,000 (LOD1 ~1,200) |
| Materials | 1–2 |
| Reuse | unique |
| Current | procedural — rafters, roof skin, boarded wall, tapered chimney |
| Final | authored GLB |

**Construction notes:** visible timber joinery, plank-to-plank variation, dark joints, weathered edges, stone chimney with painted courses. **South face open** — the camera-side opening is what keeps the player visible (`docs/09` F4). Interior depth must be readable from outside.

### 10.4 `dest.projects.desk` — Projects Desk + CRT

Visual role: the hard rectangle that identifies Projects at distance — the only right-angled object in an organic landscape. Silhouette: low horizontal desk mass, one boxy monitor. Plank desk with grain and end-grain; beige CRT with real bezel depth and a cable. 2,000–3,000 tris, 1024 shared timber atlas, unique, no LOD. Emissive screen stays a separate small mesh on the shared emissive material.

### 10.5 `dest.achievements.shrine` — Shrine + Dais

Visual role: the only symmetrical architecture in the world. Silhouette: small gabled shrine on a stepped circular dais. Carved stone relief, fitted dais courses, timber posts with visible joints. 2,500–4,000 tris, 1024 stone+timber, LOD1 ~1,000 at ~45 u, unique. **No headstone or funerary forms** (DD-19 lineage; the master reference's gravestones are rejected).

### 10.6 `dest.education.desk` — Education Study Desk

Visual role: close-range identity is the **vertical instrument cluster** — globe, astrolabe rings, upright books, quill. **No screen anywhere.** Carved apron more ornate than the Projects desk. Books with visible page edges. Lamp positioned for the approved night light (DD-22). 2,500–3,500 tris, 1024 shared timber atlas, unique.

### 10.7 `prop.bridge` — Bridge

Visual role: the first object the player stands on. Currently the weakest thing in the spawn view. Requirements: **real board thickness**, irregular plank widths, cut stringers, and **abutments that meet both banks** — the current version samples one height and floats. 800–1,500 tris, 512 shared timber atlas, unique.

### 10.8 `prop.rock.{a,b,c}` — Major Rock Set

Visual role: appear at every path edge, stream bank and the mid-route landmark. Silhouette: designed facets, not deformed spheres — one larger, two smaller, clustered. Painted value variation with **moss accents on upper faces only**. 200–400 tris each, shared 512 stone atlas, 40–60 instanced placements, 3 variants (2 on mobile).

## 12. Procedural-vs-authored decision matrix

| Criterion | → Procedural | → Authored GLB |
|---|---|---|
| Silhouette carries identity | no | **yes** |
| Seen close-up by the player | no | **yes** |
| Defined by parameters, not shape | **yes** | no |
| Must match terrain at runtime | **yes** | no |
| Benefits from painted texture | no | **yes** |
| Download cost vs generation cost | generation cheaper | download cheaper |
| Needs an artist's judgement | no | **yes** |

### Verdict

| Stays procedural | Becomes authored |
|---|---|
| Terrain heightfield — parameters, not geometry; a 20k-tri mesh download to replicate a height function is strictly worse | Both hero trees |
| Path ribbons / terrain paint — must track the height function | Four destination sets |
| Water surface **geometry** — follows a spline over terrain (the *material* needs rework, §20) | Bridge |
| Distant hills — silhouette only, beyond fog | Major rocks |
| Backdrop tree ring — never resolved close | Birch, conifer |
| Sky dome — a gradient | All vegetation |
| Small pebbles — sub-0.3u | Workshop props |
| Collision volumes — never rendered | |

**8 P0 + 9 P1 = 17 assets to source. 5 atlases.**

## 13. Gemini reference workflow

Gemini is now part of the art pipeline, producing **art direction references — never assets**.

| Gemini produces | Gemini does not produce |
|---|---|
| Concept art | 3D geometry |
| Per-asset reference sheets | Textures used directly as UV maps |
| Style exploration | Anything dropped into the scene as-is |
| Asset turnarounds | |

**A Gemini image is never a game asset.** It is the brief a modeller works from.

The **Explorer Unit 7-B** sheet is the model for this process — a formal turnaround with front/side/back views, a palette strip, and an explicit spec panel. That sheet worked precisely because it specified *properties*, not just appearance.

I will not generate these sheets unless asked. §14 specifies what they must contain so you can produce them.

## 14. Reference-sheet requirements

One sheet per P0 asset, eight sheets total. Each must contain:

| Element | Requirement |
|---|---|
| **Front view** | orthographic, neutral lighting |
| **Side view** | orthographic |
| **Rear view** | orthographic |
| **3/4 view** | the hero angle |
| **Close-up** | the detail that carries identity — bark grooves, roof joinery, instrument cluster |
| **Scale reference** | Explorer Unit 7-B (1.4 units) beside the asset, same scale |
| **Material references** | swatch callouts: bark, timber, stone, foliage, metal |
| **Colour palette** | swatch strip, as on the character sheet |
| **Silhouette notes** | the asset as a flat black shape — the identity test |
| **Construction notes** | how it is built: joinery, branching, courses, joints |
| **WebGL quality level** | triangle target and texture size from §10 |

**The scale panel is a check, not a source (DD-33).** Sheets supply silhouette, construction, proportion, material and detail; **dimensions come from `docs/01` §12, `docs/09` §4 and §10–§11 of this document**, never measured off a sheet. The delivered sheets show 1.7–1.8 m humans instead of the Explorer this table asks for — those figures are artifacts (C-9) and carry no units. Author at world scale per §15 and check against a 1.4-unit reference per §18.

### Prompt guidance

State the target explicitly every time — *premium stylized realism, hand-authored indie game art, storybook environment, low-poly geometry, hand-painted material language*. Explicitly exclude: generic low-poly, cartoon fantasy, Minecraft, Fortnite, generic AI landscape, photorealistic.

**Style coherence across 17 assets is the dominant risk.** Generate all eight P0 sheets in one session against the same style anchor, and include a previously approved sheet as a reference image so the set stays consistent.

## 15. Asset naming conventions

```
category.subject.variant          logical id      tree.oak.broad
kebab-case-filename.glb           file            hero-oak-broad.glb
kebab-case-filename-lod1.glb      LOD             hero-oak-broad-lod1.glb
atlas-name.ktx2                   texture         bark-foliage.ktx2
```

Rules:
- Logical id is stable forever; the filename may change
- **Origin at base centre, on the ground plane.** Trees at trunk centre, desks at footprint centre, dais at disc centre
- **−Z is forward**, matching the player and camera
- **+Y up. 1 unit = 1 metre. Export at scale 1** — never rescale in code
- One root node per asset, no empties, no cameras, no lights
- Materials named for their atlas (`timber`, `stone`, …) so ingest can map them
- No baked lighting in albedo — assets must hold up across all four time-of-day presets

## 17. Performance budgets

Carried from `docs/09` §16, with the measured M4B position stated honestly.

| Metric | Budget | M4B measured |
|---|---|---|
| Draw calls, desktop | **≤ 120** | **273** ❌ |
| Draw calls, mobile low | ≤ 70 | 261 ❌ |
| Triangles visible | 150k–350k | not measured |
| Materials | **≤ 12** | 12 ✓ |
| Textures | ≤ 10 | 0 (none yet) |
| Texture memory | ≤ 24 MB | 0 |
| Shadow map | 2048 / 1024 low | 2048 ✓ |
| Initial load | ≤ 6 MB compressed | ~0 (all generated) |
| Unique assets | ~22 | 22 ✓ |

**Draw calls are 2.3× budget.** Moving to GLBs does not fix this by itself. What fixes it, in order of impact:

1. Merge player (15 meshes) and bridge (11) — unblocked, mine
2. Shared atlas materials collapsing state changes
3. Spatially partitioned instance groups so culling works
4. Stop vegetation and backdrop casting shadows

**No real-device measurement exists.** Every mobile budget remains reasoned, not observed. FPS figures from the Playwright environment (2.5 desktop / 4.1 mobile) are software WebGL with no GPU and must never be quoted as hardware performance.

## 18. Validation checklist

Run per asset at ingest. Any failure blocks the swap.

**Geometry**
- [ ] Scale correct against a 1.4-unit reference
- [ ] Origin at base centre, on the ground plane
- [ ] −Z forward, +Y up
- [ ] Triangle count within §10/§11 budget
- [ ] No n-gons, no loose vertices, no inverted normals
- [ ] Single root node; no cameras, lights or empties

**Material**
- [ ] Uses a shared atlas material after ingest — brings none of its own
- [ ] No baked lighting in albedo
- [ ] Alpha-tested, not alpha-blended
- [ ] Material count unchanged after adding the asset

**Visual**
- [ ] Silhouette identifiable as a flat black shape at its intended viewing distance
- [ ] Reads correctly in all four time-of-day presets
- [ ] Sits at home beside the already-approved assets (coherence)
- [ ] Would look at home in the Gemini references

**Camera**
- [ ] Tree canopy underside clears 5.0 units
- [ ] Structures registered in the `occluders` group
- [ ] Player remains visible at the interaction position

**Performance**
- [ ] Draw calls measured before and after
- [ ] Instanced where `expectedInstances > 1`
- [ ] LOD present where §8 requires it
- [ ] Mobile density applied

## 19. Replacement workflow

The whole pipeline exists to make this short.

```
1. Drop  hero-oak-broad.glb  into public/assets/environment/trees/
2. Edit ONE registry line:
     source: { kind: 'procedural', build: buildHeroOakBroad }
   →  source: { kind: 'glb', url: '/assets/environment/trees/hero-oak-broad.glb' }
3. Run the §18 checklist
4. Tune placement / LOD distance if needed
```

No gameplay file is touched. No component signature changes. The procedural builder stays in the codebase as a fallback and as documentation of intent.

**Rollback** is the same edit reversed.
